GateIO Proxy MCP vs Charles / Proxyman 对比文档

一、工具定位对比

维度Charles / ProxymanGateIO Proxy MCP
本质独立的 GUI 抓包工具集成在 IDE 中的 AI 驱动抓包 + Mock 服务
交互方式鼠标点击、菜单操作自然语言对话（"帮我找登录接口"）
数据消费者人眼看AI 分析 + 人看
工作流抓包 → 切到 Charles 看 → 切回 IDE 改代码全程在 Cursor 内完成，不切窗口
Mock 方式GUI 配置 Map Local / Map Remote自然语言描述，AI 自动创建规则
价格Charles $50，Proxyman $49-69/年免费开源

二、核心优势

1. 不用离开 IDE

传统流程：

写代码 → 切到 Charles → 找接口 → 看数据 → 切回 IDE → 改代码 → 切到 Charles 验证

MCP 流程：

写代码 → 对话框里说"帮我找 XX 接口的返回" → AI 直接给你数据 → 继续写代码

窗口切换次数从 6+ 次降到 0 次。

2. AI 理解你的意图

你说的话Charles 需要你做的MCP 自动做的
"找持仓列表接口"自己在几百条请求里用眼找traffic_search 搜索，直接返回匹配的接口
"这个接口返回了什么"点开请求 → 点 Response → 复制 JSONtraffic_read_body 读取，AI 直接分析
"把 vipLevel mock 成 5"Map Local → 新建规则 → 编辑 JSON → 保存一句话，AI 自动找到接口、读取原始响应、修改字段、创建规则
"对比接口返回和 Model 字段"手动复制 JSON → 和代码逐个对比AI 自动读取两端数据，输出对比表格

3. Mock 效率差异巨大

Charles 创建一个 Mock 的步骤（Map Local）：

  1. 找到目标请求
  2. 右键 → Map Local
  3. 选择或创建本地 JSON 文件
  4. 用编辑器打开 JSON 文件
  5. 修改目标字段
  6. 保存
  7. 刷新验证

MCP 创建一个 Mock 的步骤：

  1. 说"把 /api/user/info 的 vipLevel mock 成 5"
  2. 完成

更极端的场景——选中 Model 字段 mock：

MCP 可以做到你选中一个 Dart Model 的字段，说"mock 成 1"，AI 会：

  • 自动分析 Model 类名和 JSON key
  • 搜索代码找到哪些 API 返回这个 Model
  • 读取这些 API 的实际响应
  • 只修改对应字段
  • 给所有相关接口创建 mock 规则

Charles / Proxyman 要实现同样的效果，你需要自己完成上面每一步。

4. 与代码上下文打通

MCP 工具运行在 Cursor 内部，AI 同时能看到你的代码和抓到的流量数据。这意味着 AI 可以做 Charles / Proxyman 永远做不到的事：

  • "这个接口返回了哪些字段是 Model 里没有的？"
  • "帮我根据这个接口的返回生成 Dart Model"
  • "对比线上返回和 Model 的字段差异"

5. 团队协作与自动化

  • Mock 规则存在 SQLite 中，可以通过脚本导入导出
  • Skill 文件（SKILL.md）可以放在项目仓库里，团队成员 clone 即可使用
  • 标准化的抓包/Mock 工作流，减少"我这里能复现你那里不行"的问题

三、劣势与局限

维度说明Charles / Proxyman 的优势
GUI 可视化MCP 没有流量瀑布图、时间线视图请求列表、响应预览、JSON 树形视图非常直观
实时性MCP 需要主动查询，不能实时刷新实时展示每一条请求
高级抓包功能不支持 WebSocket、gRPC、SSL Pinning bypass更完整的协议支持
断点调试不支持请求断点支持 Breakpoints 拦截并手动修改
带宽限速不支持模拟弱网Charles 有 Throttle 功能
请求重发不支持 Compose / Repeat可以修改并重发请求
独立运行依赖 Cursor IDE独立应用，不依赖 IDE
学习曲线需要了解 MCP、Skill 概念打开即用
稳定性AI 理解可能有偏差GUI 操作确定性更高

四、使用教程

前置准备

1. 安装项目：cd gateio-proxy-mcp && uv sync 2. 配置 Cursor MCP：Cursor Settings → MCP → 添加 gateio-proxy 3. 安装 Skill：bash install-skill.sh

基础用法

操作说法
启动代理"启动代理" 或终端执行 uv run gateio-proxy-start --setup-proxy
查看流量"显示最近的请求" / "搜索 URL 包含 /api/v1/user 的请求"
读取响应"读取 req-3 的响应体"
创建 Mock"把 /api/v1/user/info 的返回 mock 成 {"code": 0, "data": {"vip": 5}}"
管理 Mock"列出所有 mock 规则" / "关闭第一条 mock 规则"
停止代理"停止代理"

证书安装（HTTPS 抓包必须）

iOS 模拟器：

  1. 模拟器 Safari 访问 http://mitm.it
  2. 下载 Apple 证书
  3. 设置 → 通用 → VPN与设备管理 → 安装
  4. 设置 → 通用 → 关于本机 → 证书信任设置 → 启用

Mac 浏览器：

  1. 浏览器访问 http://mitm.it → 下载证书
  2. 双击安装到钥匙串
  3. 钥匙串中找到 mitmproxy → 信任 → "始终信任"

五、效率提升技巧

技巧说明示例说法
选中字段直接 Mock选中 Dart Model 属性，AI 自动找接口、读响应、改字段、建规则选中 vipLevel 字段 → "mock 成 5"
批量 Mock 边界一句话覆盖多个测试场景"把 list 字段分别 mock 成空数组、1 条、100 条"
基于真实数据微调先抓包拿真实数据，再修改特定字段 mock"把 price 改成 0，其他不变，mock 这个接口"
接口对比发现问题AI 自动对比接口返回和 Model 字段差异"对比 /api/user/info 返回和 UserInfoModel 字段"
Mock 异常状态码测试错误处理逻辑"把 /api/payment/create mock 成 500"
模拟延迟测试 loading UI 表现"mock 正常返回，但延迟 3 秒"
快速开关 Mock调试完禁用而不删除，方便反复测试"关闭所有 mock" / "打开所有 mock"
抓包 + Mock 回归抓正常数据后逐个 mock 异常值验证不污染代码，比 if(debug) 更干净

六、总结

GateIO Proxy MCP 不是要替代 Charles / Proxyman，而是补充它们在 AI 开发工作流中的不足。
  • 需要快速查看/Mock 接口数据且不想离开 IDE → 用 MCP
  • 需要深度网络调试（断点、重发、限速、WebSocket） → 用 Charles / Proxyman
  • 两者可以同时使用，MCP 代理和 Charles 代理可以配置不同端口
