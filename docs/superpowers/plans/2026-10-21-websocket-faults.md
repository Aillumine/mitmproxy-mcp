# WebSocket 中途故障模拟

沿用已确认的研究、规划、验证流程；扩展现有 WebSocket Mock 功能分支，完成后合入最新 main。

1. 新增 `ws_fault` 类型，沿用规则库、导入导出和 API。每条连接在握手完成时捕获匹配的故障规则，可叠加多条；修改、停用只影响新连接。
2. 触发：`trigger=messages`，`after_messages=N`；延迟/暂停从第 N+1 条开始，关闭/中断在第 N 条之后发生，0 表示建连后立即发生。`trigger=time`，`after_ms` 从 WebSocket 建立计时，即使没有消息也能触发关闭或暂停。
3. 动作：`delay` 原样延迟，使用规则 `delay_ms` 加 `jitter_ms` 范围的随机抖动；`pause` 暂停 `duration_ms` 后恢复；`close` 发送指定合法关闭码和原因；`abort` 不发送 WebSocket 关闭帧，突然切断传输。支持概率，固定 seed 可重复随机序列。
4. 作用方向为 client/server/both。消息计数按方向，双向时合计。默认放行 Socket.IO 的建立/心跳消息，不计入业务条数；可关闭豁免。原生 WebSocket ping/pong 控制帧始终由协议层处理。
5. 每方向 FIFO 队列：延迟不改变消息正文或二进制 opcode，不允许后到的业务消息越过已暂停消息；注入重放有专门标记，跳过二次匹配，避免递归。连接关闭、客户端离开、addon 停止时取消计时器与队列任务。
6. 浏览器提供类型、方向、触发、动作、条数/时长、暂停时长、抖动、概率、心跳开关与关闭码/原因，JSON 配置可继续编辑；内置可复现的示例。MCP 描述与 README 同步。
7. 验证：配置拒绝非法值及无损往返；消息顺序、独立连接计数、时间触发、概率和抖动边界、心跳放行、队列取消；真实 mitmdump 对 WS/WSS 离线与真实上游分别验证延迟、暂停恢复、正常 Close 与无关闭帧断连。运行本机后端测试、前端测试、类型检查和构建；审查后本地提交并合并 main。

实现边界：这是代理层消息故障模拟，不能等同于底层 TCP 丢包、操作系统断网或保证发送 TCP RST。不修改任何设备或系统代理；不执行真机验收。

## 验证与审查结果

- 本机后端测试 439 passed，3 项设备测试按 marker 排除。真实 mitmdump 集成共 28 项，覆盖 WS/WSS、真实 TLS 上游、暂停与心跳豁免/超时、消息顺序、按条数关闭、空闲连接定时断开、0 条立即关闭、二进制双向延迟、重连后重新计数，以及此前 HTTP/WS Mock 回归。
- 前端 150 项测试、TypeScript 检查和生产构建通过；Vite 仍有已有的大 chunk 提示。
- 浏览器验证：故障类型和独立控件可用；将规则改成建连 5 秒后关闭、关闭码 4005 并保存，刷新重新打开后字段保留；1280 像素视口下编辑器右边界和页面宽度均不超出视口。
- 审查发现并修复：延迟叠加按条数关闭时，必须在第 N 条真正 SendData 后才关闭；关闭回调执行后立即移除，避免流量记录保留连接任务引用；长说明曾撑破分栏，已固定宽度并折叠高级 JSON。
- 生命周期与容量：连接结束、客户端离开、addon 停止都会取消任务；延迟重放有专用标记，不会递归命中；每连接最多暂存 1000 条或 8 MiB，超限以 1009 关闭；合法关闭码、关闭原因字节数、触发参数、概率与随机种子在保存前校验。
- 合并范围：包含前次 WS/WSS Mock 提交及本次故障模拟；不包含其他工作树的变更。
