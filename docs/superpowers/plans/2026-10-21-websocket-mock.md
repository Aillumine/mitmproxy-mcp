# WebSocket Mock 实施计划

目标：保留 HTTP 规则兼容性，支持真实连接上的文本消息替换、丢弃和响应，以及不访问真实服务器的 WS/WSS 服务模拟。

1. 规则模型：增加 `mock_type`（http / ws_message / ws_server）和 `ws_config`。老数据库自动迁移为 HTTP；增改、列表、导入导出、MCP 和控制 API 保持字段一致。非法配置在保存前拒绝。
2. 消息规则：按规范化 WS URL、方向和文本内容匹配；支持 replace/drop/reply；跳过二进制和注入消息，避免响应递归。异步延迟不阻塞其他连接。
3. 服务模拟：通过仅监听回环地址的本地端点完成握手，使用一次性会话路径；代理采用 lazy 连接，避免访问真实目标。支持连接推送、客户端消息响应、WebSocket 控制帧；Socket.IO 支持 Engine.IO v4 WebSocket 直连、namespace connect/disconnect 与 ping/pong 超时。每个会话独立，关闭后清理定时任务。
4. 浏览器：现有 Mock 页增加类型、消息方向/动作/匹配，以及服务协议/推送配置；显示类型与命中次数，支持编辑、启停、导入导出。
5. 验证：数据库迁移与校验、CRUD 往返、URL/方向/消息匹配、替换/丢弃/响应、任务清理；真实 mitmdump 子进程验证 WS 和 WSS 离线握手（不可解析目标）、Socket.IO 连接/心跳、真实上游消息替换和 HTTP 回归；前端状态测试、类型检查、构建及浏览器查看。
6. 审查与提交：检查新注释双语、无真实数据库/设备/系统代理写入；更新 README，提交源码、测试和前端构建资源。仅本地提交，不默认推送。

边界：消息规则处理 UTF-8 文本消息；二进制消息透传。Socket.IO 不实现 polling、协议 v3、二进制附件和自动业务 ACK；可用原始文本响应规则显式定义事件/ACK。服务配置在新连接时捕获，消息规则实时生效。

## 验证与审查结果

- 后端本机测试：387 passed，3 项设备测试按 marker 排除。
- 真实 mitmdump 集成：6 passed，包含不可解析域名的 WS/WSS 模拟、推送、回复、WebSocket ping/pong、Socket.IO open/connect/事件/心跳超时、真实上游替换/回复/二进制透传/实时停用及 HTTP 兼容。流量记录保留原始 URL 和规则标记。
- 前端：147 项测试通过，`tsc --noEmit` 和 Vite 构建通过；构建仍有现有的大 chunk 提示。
- Chrome 页面检查：两类 WSS 规则均出现在列表，编辑控件可用，修改内容匹配会同步到 JSON 配置；保存路径由控制分发的往返测试覆盖。
- 审查清单：旧规则迁移后保持 HTTP 类型；结构迁移有数据库写锁；非法配置在保存前拒绝；导入先校验再清空；回复不递归；连接结束取消推送/心跳；延迟使用异步等待；所有测试使用临时数据库/证书/代理端口；未修改设备或系统代理；未执行真机验收。
